# 静态发布故事正文与图片

## 问题

当前 `works/` 作品在普通阅读时下载完整 ZIP，浏览器核对摘要后再解析全部文件并为所有画面创建 Blob URL。大作品会在首屏前下载整包，峰值内存可能同时包含 ZIP、解压数据与图片 Blob；稳定的图片地址、旁白和正文也不在初始 HTML 中，搜索引擎、图片搜索、无 JavaScript 访问及分享预览只能看到有限的页面外壳。

阅读站应继续把维护者审阅的原 ZIP 作为来源与版本证据，但面向读者和搜索引擎发布经过同一验证流程生成的静态公开内容。正常阅读不应依赖浏览器下载或解压 ZIP。

## 目标结果

- 审阅来源、公开发布物和阅读体验职责分开：ZIP 保留为只读来源；构建产物提供可直接请求的公开清单、图片与故事页面。
- 读者按需加载稳定的 HTTP 图片文件，降低首屏下载量和峰值内存，并继续使用现有多页、长卷、收藏、进度及推荐功能。
- 每篇故事的初始 HTML 包含可索引的实际内容、图片引用和完整元信息，不依赖客户端 JavaScript 才能被理解。
- 发布物仍满足现有署名、来源、许可、AI 披露、哈希、隐私、项目子路径和不可信内容约束。

## 验收标准

### 静态公开内容

- [ ] 每个已收录 `works/` ZIP 都生成一份公开故事清单及其实际引用的图片；图片字节与已验证 ZIP 中对应条目完全一致，不重编码、不改写元数据。
- [ ] 公开清单仅包含现有允许公开的字段和阅读所需的资源信息；提示词、内部生成记录、未引用文件及其他私有 ZIP 条目不进入任何 HTML、清单、目录、日志或部署资源。
- [ ] 每个公开图片资源具有稳定、版本隔离的 HTTP URL；同一路径作品更新后不会把旧清单、旧 HTML 与新图片混合，也不会依赖手工清缓存。
- [ ] 原 ZIP 的路径、字节、大小与 SHA-256 继续记录并可供维护流程核验，但正常线上阅读、搜索抓取和页面渲染均不请求 ZIP，也不创建故事图片 Blob URL。
- [ ] GitHub Pages 部署产物不同时携带仅供来源保存的 ZIP 和同内容静态图片；保留 ZIP 的源码仓库与面向访问者的部署体积分别受现有容量检查保护。

### 加载与内存

- [ ] 直接打开任一线上故事时，标题和首屏内容可在完整故事资源下载结束前显示；非首屏图片按浏览器原生延迟加载，不因初始化阅读器而全部下载。
- [ ] 普通线上阅读的网络请求中没有 `.zip`；图片响应可由浏览器正常缓存，重复访问及前后篇导航不重复获取未变资源。
- [ ] 80 幅、总公开图片接近现有 256 MiB 解压上限的合法作品可打开，并独立覆盖单图接近 12 MiB 的边界（按所有者确认保留现有限制）；首屏不需要分配与完整 ZIP 或全部画面总量等大的单一 JavaScript 缓冲区。
- [ ] 本地 ZIP 试读仍可在浏览器中使用现有受限解析流程，并与线上静态阅读明确分开；本地试读不改变公开目录或生成部署文件。

### SEO、无脚本与可访问内容

- [ ] 每个规范故事 URL 的初始 HTML 在禁用 JavaScript 时仍包含作品标题、简介、原著/出处、公开署名与披露、按顺序排列的画面、旁白以及可访问的站内导航。
- [ ] 初始 HTML 中每幅画面使用可抓取的同源或已批准来源 HTTP URL，并提供有意义的替代文本、旁白关联、固有宽高和适当的加载提示；首幅画面可作为页面及社交分享主图。
- [ ] 每篇故事具有唯一且正确的 `<title>`、description、canonical、Open Graph/Twitter 元信息和与页面可见内容一致的 `CreativeWork` 或更合适的结构化数据；用户内容只能作为转义文本或结构化值，不能注入标记或脚本。
- [ ] `sitemap.xml` 收录所有规范故事页；可公开索引的故事图片通过图片 sitemap 信息或等价的可验证页面关系关联到所属故事。旧动态入口指向规范故事 URL，避免重复内容索引。
- [ ] 构建测试可从生成 HTML 直接验证标题、正文、图片、canonical、结构化数据与站点项目子路径；不以执行客户端 JavaScript 后的 DOM 作为 SEO 完成证据。

### 完整性与兼容性

- [ ] 发布前仍验证 ZIP 大小、结构、CRC、文件数量、解压总量、图片格式、图片大小、故事结构及声明的图片哈希；任一失败都阻止该作品产生或更新公开发布物。
- [ ] 公开清单保留每幅图片的 SHA-256 和来源 ZIP 版本身份；目录、故事 HTML、清单和图片必须来自同一已验证作品版本。
- [ ] 现有 `stories/<slug>/story.json` 兼容作品继续可构建和阅读；旧 `reader.html?story=` 分享链接、本地试读链接、书目/分类路由及 GitHub Pages 项目子路径继续有效。
- [ ] 独立部署的同一阅读器仍能读取选定公开仓库的最新已发布目录和静态故事资源，无需为每篇新增作品修改前端源码；远程暂时不可用时不回退到版本不一致的混合资源。
- [ ] `pnpm test` 与 `pnpm build` 覆盖生成、隐私排除、字节一致性、版本更新、无 ZIP 阅读、延迟加载标记、SEO 元信息、无脚本正文、旧链接和项目子路径，并在完整现有作品集上通过。

## 约束

- Node 24、仓库固定的 pnpm 版本、无第三方运行时依赖；站点保持纯静态，不增加服务端路由、数据库或运行时解压服务。
- 故事 ZIP、清单与所有文字均为不可信输入；沿用现有路径限制、字段 allowlist、格式检查和文本渲染规则。
- 保留现有作者/投稿者区分、来源许可、联系方式、转载条件、原文、AI 披露、模型信息及图片哈希语义；代码许可不扩大作品授权。
- 继续兼容 GitHub Pages 项目子路径、远程目录来源与浏览器缓存；生成资源不得使用绝对根路径。
- 构建失败必须保持上一份完整发布物，不得留下部分更新或跨版本资源引用。

## 非目标

- 不改变投稿者提交单个拾趣 ZIP 的流程，不要求投稿者手工维护展开目录。
- 不删除、重写、重新压缩或对外提供原 ZIP 下载入口。
- 不增加账号、评论、浏览量、付费、DRM、水印生成或权属判断。
- 不重做阅读页视觉风格、故事排序、信息架构或多页/长卷交互。
- 不承诺搜索引擎收录或排名；仅保证页面满足可抓取、可理解和可验证的技术条件。

## 阻塞问题

无。具体生成目录、缓存版本键和远程托管位置由后续架构计划选择，但必须同时满足版本一致性、部署容量、无需正常阅读下载 ZIP及上述 SEO 验收标准。
