# 重新设计阅读站信息架构

## 问题

当前站点只有三层：首页（hero + 全部作品网格 + 搜索/原著下拉/排序/收藏）→ `books/`（仅书名与篇数）→ `books/<书>/`（故事卡片）→ `books/<书>/<故事>/`（阅读页）。首页把"展示"和"检索"混在一张长网格里，没有精选、没有分类维度（目录已有 `theme`、`artStyle` 字段但未使用），书目总览没有封面，阅读页返回链接直接回首页、读完没有下一篇或同书推荐，访客从搜索引擎落到阅读页时缺少"你在哪里"的线索。

## 调研依据

对 WEBTOON、Tapas、哔哩哔哩漫画、Storyberries、Project Gutenberg、Standard Ebooks 及 NN/g 导航与分面导航文章的调研结论：

- 导航项对应浏览维度（按书/按类/全部），不超过 5 项；搜索常驻顶栏，与浏览分离。
- 首页顺序：精选/主推 → 最新收录 → 2–4 条分类或书目 rail → 一个"浏览全部"入口；小型精选库不做排行榜。
- 三类规范页：列表页（封面 + 一句话简介的网格）、书目详情页（简介 + 篇目列表 + 元信息 + 相关）、阅读页（极简 chrome、持续可见的返回书目、上一篇/下一篇、读完推荐）。
- 深链接访客依赖面包屑与导航高亮定位（NN/g "You Are Here"）。

## 目标 IA

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 首页 | `./` | hero → 精选（有精选时）→ 最近收录 → 按原著（书目卡片 rail）→ 按主题（主题入口）→ 继续阅读/我的收藏（仅本机有记录时显示）→ 关于与投稿简述 |
| 精选 | `featured/` | 所有维护者挑选的作品，可带一句推荐语；无精选时页面说明"尚未设置精选"，导航项隐藏 |
| 书目 | `books/` | 每部原著一张卡片：封面（取该书最近收录作品的封面）、书名、篇数、最近收录日期 |
| 书目页 | `books/<书>/` | 书名、篇数、该书包含的主题/画风标签（链接到分类页）、故事网格、其他书目入口 |
| 分类 | `themes/` | 两组入口：按主题、按画风，各显示篇数与代表封面 |
| 分类页 | `themes/<主题>/`、`styles/<画风>/` | 该分类下的故事网格，顶部说明属于哪一维度 |
| 全部作品 | `collection/` | 现首页的检索网格迁移至此：搜索框、原著/主题/画风筛选、排序、"我的收藏"切换；`collection/?q=` 承接顶栏搜索（`stories/` 已被旧版清单目录占用） |
| 阅读页 | `books/<书>/<故事>/`（保留） | 面包屑（首页 › 书目 › 书名 › 篇名）、返回书目、正文、读完区：上一篇/下一篇（同书）、同书更多、同主题更多；收藏/分享保留；不提供 ZIP 下载链接 |

主导航（阅读页以外所有页面一致）：**精选 · 书目 · 分类 · 全部作品** + 顶栏搜索；品牌标识回首页；"投稿"与"ZIP 试读"移入页脚及首页投稿段落。当前页导航项高亮。阅读页保留精简头部（返回书目、品牌、阅读方式、收藏/分享）加面包屑，并共用页脚。

## 验收标准

- [x] 阅读页以外所有页面共用同一主导航与页脚，当前页高亮；阅读页共用页脚；在 GitHub Pages 项目子路径下链接全部为相对路径，`pnpm build` 后手动打开任意生成页都能回到首页、书目、分类与全部作品。
- [x] 首页不再承载检索网格；按"目标 IA"顺序展示各区块，精选/继续阅读区块在无数据时不渲染空标题；首页仍只读取轻量目录与封面，不下载 ZIP。
- [x] 精选来源于维护者维护的单一文件，按作品稳定键引用；文件不存在时构建与运行时均视为无精选；文件格式错误或引用了目录中不存在的作品时构建报错，运行时跳过缺失项；旧版清单作品不可被引用但仍可浏览；推荐语按文本渲染。
- [x] `books/` 每张书目卡片含封面、篇数与最近收录日期；`books/<书>/` 显示该书的主题/画风标签并链接到对应分类页。
- [x] 书名、主题、画风的不同标题映射到同一 slug 时构建失败并指出冲突，不静默合并；`themes/` 列出目录中实际出现的主题与画风及篇数；`themes/<主题>/`、`styles/<画风>/` 为静态页，列出该分类全部作品；缺少 `theme`/`artStyle` 的作品不进入对应分类页，分类索引不显示空分类。
- [x] `collection/` 保留现首页全部检索能力（搜索、排序、收藏切换、空状态），新增原著/主题/画风筛选且可组合；`collection/?q=关键词` 打开时自动套用搜索词。
- [x] 阅读页顶部返回链接指向所属书目页而非首页；页面含面包屑；读完区提供同书上一篇/下一篇（按书目页排序），以及同书、同主题各不超过 3 篇的推荐卡片（不含当前篇）；本地 ZIP 试读不显示这些推荐；阅读页不再提供「下载作品 ZIP」链接（用户 2026-11-02 要求）。
- [x] `sitemap.xml` 包含精选、书目、分类及全部作品页；首页与所有构建生成的页面（书目、分类、精选、全部作品、作品页）带 canonical 与 Open Graph 元信息；`reader.html` 是动态入口，不含静态 canonical，但通过 `?story=` 打开已收录作品时由脚本把 canonical 指向该作品的静态页。
- [x] 旧链接继续有效：`reader.html?story=<编号>`、`reader.html?preview=1`、`books/`、`books/<书>/`、`books/<书>/<故事>/`、首页 `#collection`/`#contribute` 锚点跳转到对应新位置或页面。
- [x] `pnpm test` 与 `pnpm build` 通过；README 中"阅读站怎样更新"与 `pnpm build` 生成页面的描述更新为新结构。

## 约束

- 无第三方运行依赖；Node 24、pnpm 11.25.0；静态站点，无服务端路由。
- 故事内容为不可信输入：所有标题、简介、推荐语、分类名以文本渲染；分类 slug 复用 `story-url.mjs` 的 `slugify` 规则并校验。
- 保留作者、出处、AI 声明与模型信息的现有显示；不把提示词或生成记录带入新页面。
- 分类与书目页在构建时静态生成（SEO）；首页、精选、全部作品、阅读页推荐区由客户端从目录渲染，以便新增作品无需重新部署 Sites。

## 非目标

- 不做排行榜、浏览量、评论、账户或跨设备同步。
- 不解析原著回目顺序；书目内排序沿用现有"最近收录，其次篇名"规则。
- 不改变 ZIP 投稿流程、目录生成格式（`catalog.json` schema 不变）或阅读页正文的多页/长卷阅读交互。
- 不重做视觉风格；复用现有 `site.css` 组件（卡片、标签、按钮、masthead）。

## 已确认决定

- 精选文件：`site/featured.json`，形如 `{"stories":[{"path":"works/yysun/黛玉葬花与宝黛释疑.zip","note":"……"}]}`，以目录 `sourcePath` 为稳定键。
- 分类维度：主题（`theme`）与画风（`artStyle`）都作为分类，统一入口 `themes/`，画风详情页为 `styles/<画风>/`。
- 新增 `collection/` 全部作品页承载搜索、筛选、排序与收藏；顶栏搜索跳转 `collection/?q=`。
