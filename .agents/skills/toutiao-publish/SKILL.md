# 今日头条文章发布

把用户选定的已有内容做成头条「文章」。保留开场简介、图文顺序、署名和来源。没有要求重写时，不另写评论替代作品。

## 用户默认偏好

下表是用户要求保存的工作偏好。当前请求中的新选择优先；不要反复询问已确定的设置。

| 项目 | 默认设置 |
| --- | --- |

| 制作署名 | **好画好心情**，链接到[头条主页](https://www.toutiao.com/c/user/962768859041496/)。公开署名不能作为自动选择登录账号的依据。 |
| 署名行 | `制作：好画好心情 · 拾趣 · AI 生成`，用于确实使用拾趣及 AI 的作品；其他文章按实际来源署名。 |
| 开场 | 保留作品完整的故事简介，放在署名之后、第一幅图文之前，不因透露情节自行删除。 |
| 正文 | 按原顺序排列「旁白正文段落 → 插图」，图片完整，不截断旁白。 |
| 封面 | 单图，优先与标题主事件相符的画面，检查裁切后主体是否完整。 |
| 广告 | **允许广告**，选择「投放广告赚收益」。这是用户创建本技能时更新的偏好，不沿用先前草稿的「不投放广告」。 |

这些偏好不构成未来文章的自动发布授权。要求「发到头条」可覆盖该篇文章的最终提交；只要求准备、预览、查看或修改技能时不提交。

## 来源与浏览器

- 先定位选定作品。拾趣公开包可能在 `works/<投稿者>/<作品名>.zip`，包含 `故事.json`、图片和署名说明。优先用已有公开包，不为转载启动制作、运行模型或修改书库。
- 对这类包运行 [scripts/prepare_shiqu_article.py](scripts/prepare_shiqu_article.py)，提取有序图片和精简公开清单。脚本只读取已有导出包，不生成/重建作品，不修改仓库文件。其他文章直接使用用户提供的内容。
- 只传递公开排版字段，不把全部原文章节、模型记录、提示词或私有制作数据复制到浏览器或对话中。
- 默认使用内置浏览器并复用相关页。内置浏览器未登录、而用户在 Chrome 登录时，说明会话不共享，取得用户对改用该会话的选择后切换。核对账号展示名。
- 本次验证的是 `mcp__cua_repl`。先读当前工具返回的文档，不把技能示例当作跨版本 API 保证。

## 排版与设置

执行发布时读取 [references/browser-workflow.md](references/browser-workflow.md)，其中包含批量图片与超链接操作细节。

1. 从页面「写文章」入口进入编辑器，不覆盖无关草稿。
2. 应用默认偏好和用户最新修改，放入署名、完整简介、有序图文；末尾保留原作已有感悟、版本/出处、AI 改编与再使用说明、阅读站链接。
3. 包内未填作者时可以使用用户指定的刊发署名，但不要伪造包内原有作者。已有其他制作人署名时保留原作者，区分刊发者；不能用默认偏好抹去原署名。保留包内公开转载条件。图片可能仍带「未署名」水印；文章署名不会改变图片像素或元数据。要求同步改图时单独处理。
4. 图片描述栏可能限 50 字，长旁白必须作为正文段落，不截成图片描述。批量上传后核对数量与顺序。
5. 用编辑器建立链接并核对实际 `href`。HTML 粘贴可能保留文字却剥离 `<a>`；看到署名文字不等于链接成功。
6. 外链解析持续加载时不反复点确定。可以保留网址文本兜底，必须说明卡片/可点击链接未成功。若用户明确要求可点击外链且不接受降级，保持草稿并报告限制。
7. 所有排版和封面操作结束后，根据实际选中状态核对广告、封面、首发、同步微头条、AI 声明。不能只凭「点击过」判断完成。

## 发布与受阻

- 提交前核对账号、标题、完整简介、所有图片可读、图文顺序及文字、署名链接、AI 披露、来源和发布选项。
- 进入「预览并发布」。手机预览能加载时检查效果；一直空白时说明无法验证，不宣称已完成手机预览，可结合编辑器证据继续判断，不循环空等。
- 用户已要求发布且没有新事项需要决定时，继续「确认发布」，不增加固定审批关卡。工具拒绝时说明真实原因，只处理受阻部分；不要把自动审批限制说成头条规则，也不能换方法绕过。
- 登录不等于有发布资格。出现国内手机号绑定、实名认证、验证码或其他需用户完成的步骤时，保留草稿并交接页面。不索取身份材料到聊天里，不代填未知信息，不绕过验证。
- 只有看到「发布成功」「审核中」或内容管理中对应状态才报告提交完成。区分「已保存草稿」「已提交审核」「已公开发布」。最终操作超时或无返回，先查管理列表避免重复提交。
- 交付标题、状态和可用链接。受阻时指出下一步及已保存的内容，标记/保留交接页，并在最终回复内嵌结果或阻碍截图，截图存私有临时目录。
