# 小红书 / Rednote 图文发布

将用户明确选中的已有故事发布为一篇图文笔记，图片在前，正文保留故事简介并放入 awesome-shiqu 的该篇故事直达链接。默认不粘贴逐幅编号旁白，也不追加阅读站评论；用户明确要求时再添加。不要因图片受限擅自拆成多篇、把图片拼成长图或另发纯文字笔记。

## 本项目约定

| 项目 | 处理方式 |
| --- | --- |
| 图片限制 | **最多 18 张**，这是 2026-11-04 网页创作平台实测值。每次以当前上传器提示和最终数量为准，不把历史限制当作永久规则。 |
| 正文限制 | **1000 字**，以编辑器实时计数为准，不能仅靠本地字符串长度判断；本次空白/换行与平台计数不同。 |
| 标题 | 沿用已确认格式 `AI故事欣赏-原著名-篇名`，如 `AI故事欣赏-红楼梦-黛玉葬花`。另行核对当前平台标题长度限制，不把正文上限当成标题上限。 |
| 署名 | 本人的拾趣作品使用 `制作：好画好心情 · 拾趣 · AI生成`。已有其他作者时保留原署名，区分作者和刊发者，不用默认署名覆盖他人。 |
| 开场 | 保留故事完整简介，置于署名之后、故事直达链接之前。简介前后各留一个空行，不因透露情节自行删除。 |
| 旁白 | 默认省略逐幅编号旁白，用该篇故事的阅读链接替代。只有用户明确要求旁白时才按图片顺序编号，并核对对应关系与字数。 |
| AI 声明 | 在「内容设置 → 添加内容类型声明」选择 **笔记含AI合成内容**，并在正文保留 AI 画面、改编文字、非原文引述的披露。 |
| 阅读站 | 正文写 `完整故事图文阅读：<该篇故事的直达链接>`，优先使用已核实的故事页，不只给站点首页，不猜路径。首页为 `https://yysun.github.io/awesome-shiqu/`。 |
| 评论 | 默认不发阅读站评论。用户明确要求时，才按下方可选步骤添加。 |

上述约定不构成未来笔记的自动发布授权。用户要求发布该篇时可继续最终提交；只要求准备、预览、查看或修改技能时不发布。调用本技能本身不代表要求发布评论；只有用户明确要求该评论时才发送。用户说今后不需评论，不代表要求删除过去已发的评论。

## 1. 准备公开作品与浏览器

- 从本项目 `works/<投稿者>/<作品名>.zip` 或用户提供的已选公开内容读取。优先保留 `故事.json` 中的简介、有序 `pages`、来源和公开转载条件，不启动新制作、不运行模型、不改原书库。
- 需要提取公开 ZIP 时，可以复用本项目现有的 [prepare_shiqu_article.py](../toutiao-publish/scripts/prepare_shiqu_article.py)。它只提取已有公开包，不是小红书发布接口；没有该脚本时按同样边界读取已选包即可，不依赖全局安装路径。
- 图片和发布用清单放私有临时目录，不放 `stories/` 或 `dist/`。不向浏览器或公开笔记复制提示词、模型记录、私有制作数据及不相关原文。
- 默认使用内置浏览器，复用相关标签页。用户已选择其他浏览器时沿用其选择。内置浏览器与 Chrome 登录不共享；确需换会话时说明原因并取得选择，不擅自切换账号。
- 本次实测工具为 `mcp__cua_repl`。首次调用按其初始化规则获取文档；后续使用当前工具支持的接口，不沿用旧元素索引、浏览器 ID、tab ID 或安全令牌。

## 2. 上传允许的图片

1. 从 `rednote.com` 的 **Post** 进入创作服务平台，再选「上传图文」。本次目标为 `creator.rednote.com/publish/publish`，账号显示「好画好心情」。以实际页面导航为准，不保证该地址永久有效。
2. 上传前读取当前工具的文件上传文档，经文件选择器上传。该次输入为支持多选的 `input[type="file"]`，接受 JPG/JPEG/PNG/WebP，单图上限提示 32 MB。
3. 用户已允许数量受限时发布允许的部分：按原顺序取前 `min(故事幅数, 当前限制)` 张。在已知 18 张上限时直接选择前 18 张，不再上传多余图片。
4. 本次选择 36 张后，平台提示「最多只允许添加18张照片，超出部分未上传」，最终编辑器显示 `18/18`。这是已接受前 18 张，不是整个上传失败；不要重复上传导致顺序或数量混乱。
5. 展开所有图片，核对数量、缩略图和顺序。保持原顺序，封面默认第一幅；不要为封面移动图片却忘了同步旁白编号。
6. 未得到允许部分刊发的授权时，先准备好候选内容并询问，不能把本次授权推及其他故事。

## 3. 填写标题、正文和 AI 声明

默认正文顺序：署名 → 完整简介 → 本篇范围说明 → 完整故事直达链接 → 原作版本/出处、AI 改编披露及适用转载条件。用户要求替换编号旁白时，删除“以下编号对应图片”及整个旁白块，保留简介与其他说明。

范围说明应如实写成「本篇展示前18幅，完整故事共36幅。」数字来自实际作品和已上传数量，不固定写 36。默认没有编号旁白，不写“以下编号对应图片”。

- 最初带前 18 幅编号旁白的版本为 **943/1000**；用户随后选择用故事直达链接替换整段旁白，新版编辑器为 **314/1000**。默认采用简介加直达链接的简洁版本，不为用满字数补入旁白。
- 超限时先删无关标签、重复说明与多余空白；保留署名、来源和 AI 披露。若仍需实质压缩旁白或简介，提出具体方案并取得用户选择，不静默截断或错配图片。不自动增加第二篇笔记。
- 本次标题为 `input[placeholder="填写标题会有更多赞哦"]`，正文为 `div.tiptap.ProseMirror[contenteditable="true"]`。先核实当前 DOM 再使用。简介前后各用两个换行（`\n\n`），其余段落用一个换行。填写后核对编辑器和预览，确保简介前后各只有一个空段。
- 选「笔记含AI合成内容」后，确认设置区或预览明确显示该声明。正文写 AI 不能替代平台声明。
- 不因工具生成过内容就自动勾选「原创声明」。也不要把头条的「允许广告」偏好搬成小红书的「内容包含营销广告」声明；后者描述笔记是否含营销内容。
- 不添加未要求的话题、位置、群聊、组件或定时发布；推荐话题出现在编辑器中不等于已经加入正文。

## 4. 发布并确认成功

发布前核对：账号、标题、图片数量与顺序、正文范围、故事直达链接、实时字数、原作来源、AI 声明、公开范围及用户修改。用户要求附编号旁白时再核对编号。

用户要求发布指定笔记即授权最终提交。核对完毕后直接操作「发布」，无需再次确认，也无需让用户代点。若当前仍需用户登录、实名或完成验证码，或工具明确因安全规则拦截提交，保留编辑页并说明具体阻碍。

优先用页面控件点击「发布」。DOM 找不到按钮时，用最新截图定位点击。若内置浏览器报按钮位于封闭 Shadow DOM，改用页面原生键盘导航：从正文等可操作控件按 `Tab`，查看截图，确认焦点轮廓在红色「发布」上，再按 `Enter` 一次。2026-11-07 发布《王戎识李》时已验证这条路径。页面布局会变，以可见焦点为准。提交后先读取结果再决定下一步。仅通过正常 UI 操作，保持平台和工具的安全限制。

出现「发布成功」后，在「笔记管理」或个人主页核对同标题笔记。「审核中」表示已提交，回报待审核；个人主页能打开笔记后，再回报公开状态和直达链接。提交结果不确定时先查笔记管理，避免重复发帖。

## 5. 可选：明确要求后才添加阅读站评论

默认跳过本节，不因发布成功自动添加评论。只有当前任务明确要求评论时，在确认新笔记发布成功后打开该笔记的评论区；不能评论到旧帖或其他作者笔记。根据实际数据组织评论，例如：

> 完整36幅《黛玉葬花与宝黛释疑》及更多拾趣故事，可到 awesome-shiqu 阅读站阅读：https://yysun.github.io/awesome-shiqu/ （在《红楼梦》中找到本篇）

标题、幅数和书名取实际作品，保留正常网址。不承诺平台把外部 URL 变成可点击链接，不为规避平台限制拆字、谐音或伪装网址。

**本次验证过的评论输入顺序很重要：**

1. 点击评论输入框，先让编辑区真正展开，看到 **Send / Cancel**。
2. 再填写完整评论。该次可编辑节点为 `#content-textarea[contenteditable="true"]`；以当前 DOM 为准。
3. 核对评论文字与网址，再点击当前展开区的 **Send**。
4. 等评论列表出现该作者、完整评论正文和时间/评论数。确认内容在已发布评论中，而不是仍留在输入框。

不要在折叠状态直接 `.fill()` 后立即点 Send。该次这样操作虽然能看到文字，却未真正展开并提交；随后点击输入框时文字还会被清空。第一次尝试结果不明时，重新打开笔记检查是否已有评论，确认没有后再重试，避免重复评论。

## 交付与经验边界

- 记录笔记链接、实际图片数、简介与故事直达链接、AI 声明状态。仅在要求评论的任务中记录其验证结果。将用户正在查看的结果标签页保留为交付。
- 保存能看到新笔记正文与故事链接的截图到私有临时目录；任务要求评论时再包含已发布评论，在最终回复中内嵌。不要只截创作平台已返回的空上传页作为发布证据。
- 任务要求评论且笔记成功但评论失败时，明确分别报告，不把两项都说成完成；保留可继续操作的页面，不用反复发帖解决评论问题。
- 2026-11-04 实测：以「好画好心情」账号发布《AI故事欣赏-红楼梦-黛玉葬花》，接受前 18/36 幅，正文 943/1000，设置 AI 合成声明；个人主页及笔记正文核实发布，评论列表显示 1 条作者阅读站评论。没有验证其他账号、其他客户端或更高数量上限。

后续更新偏好：简介后直接放该篇故事阅读链接，不再默认添加逐幅编号旁白或发布后阅读站评论。已有评论保留，除非用户明确要求处理。
