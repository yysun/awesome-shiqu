# awesome-shiqu · 拾趣好故事

通过 GitHub PR 收藏值得读、值得回看的拾趣连环画。作者提交 ZIP，维护者审核收录；构建验证来源 ZIP，发布完整 HTML、公开清单和原字节图片，手机或电脑直接按需阅读。

[拾趣](https://github.com/yysun/shiqu)负责创作，本仓库负责精选与展示。初始版本不预置测试故事。

也可以把这里当作拾趣导出 ZIP 的查看与检查工具，在投稿前先试读自己的作品。

## 查看与检查拾趣导出的 ZIP

1. 在拾趣中下载「分镜与图片 ZIP」。
2. 打开 [ZIP 试读](https://yysun.github.io/awesome-shiqu/reader.html?preview=1)，点击「选择 ZIP 文件」，选择导出的 ZIP。
3. 切换多页或长卷，检查图片顺序、旁白和阅读效果，并核对「出处、署名与转载说明」中的公开信息及 AI 披露。

文件仅在当前浏览器中打开，不会上传、投稿或加入公开作品集。打开时会检查 ZIP 结构、路径、文件大小、图片格式及已声明的图片 SHA-256；遇到缺图或校验失败会显示错误。支持不超过 **100 MiB** 的拾趣 ZIP，包括新版 `故事.json` 导出和旧版仅含 `分镜.md` 的导出。

本地运行阅读站后，也可打开 `reader.html?preview=1` 使用同一功能；启动方法见下方「本地检查与阅读」。

## 提交一篇作品

1. 在拾趣中完成故事，下载「分镜与图片 ZIP」。检查完整 ZIP 中的文字、图片和提示词是否适合公开。
2. Fork 本仓库，把 ZIP 原样放到 `works/<你的 GitHub 用户名>/<作品名>.zip`，例如 `works/yysun/黄忠智取定军山.zip`。可以保留拾趣导出的中文文件名。
3. 发起 PR，在模板中说明出处、收录理由和展示许可。维护者审核通过后合并。

**投稿只需要一个 ZIP。** 标题、原著、图片顺序、旁白、结语、改编说明和生成模型从 ZIP 内的 `故事.json` 提取；用户名目录记录投稿者；制作署名以 ZIP 内声明为准。封面与目录自动生成，无需手写 JSON，也不用提交解压后的图片。旧版仅含 `分镜.md` 的 ZIP 仍可阅读；两者同时存在时以 JSON 为准，JSON 无效时会明确报错，不退回 Markdown。

简介兼容新版 `summary` 与旧版 `hook`；优先读取 `summary`，仅在该字段缺失时读取 `hook`。公开清单仍统一使用 `hook`，作品集卡片、阅读页与分享的显示方式不变。

阅读页的作品信息及「出处与改编说明」显示去重后的模型名。图片模型按当前每幅画面的 `image:<从 0 开始的幅号>` 取保存顺序中的最后一条生成记录，再去重；已被重绘替换的图片模型及超出当前画幅范围的记录不计入，其他生成步骤的模型仍保留。ZIP 试读与构建发布采用同一规则，来源 ZIP 的历史记录不改动。公开清单的可选 `generationModels` 字段只保存模型名字符串数组，不包含逐步生成记录或提示词；保存的原文进入完整作品清单、故事 HTML 和来源 ZIP，不展开到轻量目录；旧作品未记录模型时不显示模型信息。

作品集卡片单独显示「分镜模型」，取自分镜批次的 `plan:<起始幅号>` 模型记录；旧版整篇生成使用 `plan` 记录。可选 `storyboardModels` 字段仅保存去重后的模型名，不混入提纲、结语或图片生成模型。书架直接读取轻量目录，不为显示模型下载 ZIP；未记录分镜模型的作品不显示该项。自动发布时会重新生成含此字段的目录。

作者目录使用小写 GitHub 用户名；ZIP 文件名支持中文、大小写英文、内部空格和常用标点，无需改成拼音。每个 ZIP 不超过 **100 MiB**，含 1–80 幅画面；单张图片不超过 12 MiB，支持 PNG、JPEG、WebP。ZIP 使用普通 STORE 或 DEFLATE 压缩。

**GitHub 网页上传每个文件最多 25 MiB**；超过 25 MiB、未超过 100 MiB 的 ZIP 可通过 GitHub Desktop 或命令行提交。这是上传方式的限制，阅读器支持读取仓库中不超过 100 MiB 的 ZIP。参见 [GitHub 上传文件说明](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)与[大文件限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。操作步骤见 [贡献指南](CONTRIBUTING.md)。

## 阅读站怎样更新

| 阶段 | 自动完成的工作 |
| --- | --- |
| 发起 PR | 检查 ZIP 格式、分镜、缺图、图片格式、路径及文件大小；运行测试和构建 |
| 维护者合并到 `main` | 验证当前来源，生成静态公开资源和故事 HTML，再部署 GitHub Pages |
| 打开书架 | 优先读取选定仓库已部署 Pages 的轻量目录，只载入目录和封面 |
| 打开故事 | 先显示 HTML 正文，按浏览器原生延迟加载 HTTP 图片；不下载 ZIP，不分配整包图片缓冲 |

公开资源位于 `public/<阅读标识>/<版本 SHA-256>/`，版本涵盖公开字段、每幅图片哈希和来源 ZIP 的路径、大小与 SHA-256。网站自动生成稳定的阅读标识，中文原名保留在仓库中。修订时保持作者目录和 ZIP 文件名不变，可保留分享链接，打开时读取当前收录版本。

Sites 与 GitHub Pages 可以使用同一套阅读器。独立阅读器读取选定仓库 Pages 的 `catalog.json` 和同版清单/图片，因此新增作品不需要重新部署阅读器。远程目录不可用时可使用完整的本地目录；选中某版本后若资源不可用，显示错误，不替换成另一版或 ZIP。

## 连接作品仓库

`site/config.json` 指定 GitHub 来源：

```json
{
  "github": {
    "owner": "yysun",
    "repo": "awesome-shiqu",
    "branch": "main",
    "directory": "works",
    "catalog": "catalog/catalog.json"
  },
  "preferRemoteCatalog": true
}
```

这里配置的是阅读器连接目标，不代表仓库已经建立或已经发布。使用其他 GitHub 账号时修改 `owner` 和 `repo`。作品仓库须公开且已部署 GitHub Pages；阅读器根据 owner/repo 推导 Pages 地址。branch/directory/catalog 保留为来源管理配置；线上读取的是已部署的根目录 catalog.json。不在前端配置 GitHub Token。

## 本地检查与阅读

准备 Node 24 和 pnpm 11.25.0。项目没有第三方运行依赖。

```bash
pnpm add:story '/path/黄忠智取定军山.zip' --author yysun --slug '黄忠智取定军山'
pnpm test
pnpm build
pnpm preview
```

`add:story` 是可选的校验与复制快捷方式；`--slug` 指定保存的作品文件名，不含 `.zip`，可以直接填写中文名。直接把 ZIP 放进对应目录也可以。打开终端显示的地址，检查翻页、长卷、手机显示、收藏与阅读进度。`pnpm validate` 单独检查内容；`pnpm catalog` 构建并生成指向 Pages 静态资源的来源审阅索引，供维护核对；线上目录随 Pages 同批部署，不由源码分支的索引决定。

`pnpm preview` 与 `pnpm dev` 只读取本次 `pnpm build` 生成的本地目录、故事 HTML、公开清单和图片，避免远程旧目录覆盖本地修改。预览服务器仅在返回配置时关闭远程目录优先，不修改 `site/config.json` 或构建文件；线上静态站仍按发布配置连接 GitHub。修改预览服务器代码后需重启预览服务。

`pnpm build` 会生成对搜索引擎友好的静态页面。站点结构：首页（精选、最近收录、按原著、按主题与画风、本机的继续阅读与收藏）→ `featured/` 精选 → `books/` 原著书目（封面、篇数、最近收录）→ `books/<原著>/` 书目页（主题/画风标签、故事列表、其他书目）→ `themes/` 分类索引（主题与画风两组）→ `themes/<主题>/`、`styles/<画风>/` 分类页 → `collection/` 全部作品（搜索、原著/主题/画风组合筛选、排序、我的收藏；顶栏搜索跳转到 `collection/?q=关键词`）→ `books/<原著>/<作品名>/` 作品页（面包屑、返回书目、同书上一篇/下一篇、同书与同主题推荐）。故事页初始 HTML 包含全部画面、旁白、出处、署名、披露与原文，禁用 JavaScript 也能阅读；书目、分类页同样为静态页；首页、精选、全部作品与阅读页推荐区由浏览器从轻量目录渲染，新增作品无需重新部署 Sites。故事页带 CreativeWork 结构化数据和 Twitter/首幅分享图；所有页面带 Open Graph 元信息；配置了 GitHub 仓库时还会生成规范链接（canonical）与 `sitemap.xml`。空作品集也会生成带提示的书目与分类页。旧链接 `reader.html?story=<编号>` 与首页 `#collection` 锚点继续有效（后者跳转到 `collection/`）。

不同书名、主题或画风若映射到同一页面地址（例如仅标点或空格不同），构建会报错并列出冲突标题，不会静默合并。

**精选**由维护者在 `site/featured.json` 指定，按 `works/` 路径引用已收录的 ZIP，可附一句推荐语（不超过 200 字，按文本显示）：

```json
{
  "stories": [
    {"path": "works/yysun/林黛玉初进贾府.zip", "note": "从黛玉的眼睛第一次看见贾府。"}
  ]
}
```

文件不存在时站点没有精选（首页不显示精选区，导航隐藏"精选"）；文件格式错误或引用了未收录的作品时 `pnpm build` 失败；浏览器端遇到目录中暂时不存在的条目会跳过。旧版 `stories/` 清单作品没有 ZIP 路径，不能被精选引用。

本地 ZIP 未提交时，日期暂用文件修改日期；合并后使用 Git 记录中的首次提交日期。原有 `stories/<slug>/story.json` 格式与 `pnpm import:story` 仍可构建阅读，也使用同样的静态发布流程；无需复制一套无版本图片。

多页模式一次列出全部画面，采用上图下文布局：窄屏（不超过 760px）一列，中屏（761–1023px）两列，宽屏（1024px 起）三列，图片随各列宽度等比缩放，向下滚动阅读；长卷模式保持单列连续阅读。两种模式均记录阅读进度，切换时保留当前画页。

## GitHub 设置

创建并推送独立仓库后，在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。主分支工作流会自动生成目录并部署；成功地址由部署步骤返回。

`check` 和 `build` 只读来源；PR 不写仓库。每次构建都从当前检出的已审核来源生成完整 `dist/`，仅 main 的构建产物上传并部署到 Pages。生成的 JSON 和图片只进入部署产物，不提交到 Git；工作流不需要仓库内容写权限，也不依赖额外的发布分支。

本地和 CI 构建均只发布当前收录版本，不从旧 `dist/` 或历史部署恢复资源。作品更新后，旧版本资源随下一次成功部署移除；已打开或缓存的旧页面可能需要刷新，作品的规范阅读链接保持不变。删除来源撤下作品后，下一次成功部署也会移除其公开资源；源码 Git 历史仍保留存档。源码 ZIP 总量与完整部署体积分别限制为 950 MiB，ZIP 解压上限保持 256 MiB。构建在暂存目录完成，验证失败保留上一份 dist，晋升失败会恢复上一份 dist。

## 目录

| 路径 | 用途 |
| --- | --- |
| `works/<GitHub 用户名>/<作品名>.zip` | 经 PR 审阅的作品原始存档，保留中文原名 |
| `catalog/catalog.json` | 可选的来源审阅索引；线上读取部署根目录 catalog.json |
| `dist/public/<id>/<version>/` | 公开清单与原字节图片；封面复用首幅 |
| `site/featured.json` | 维护者指定的精选作品 |
| `site/` | 书架、阅读器、ZIP 解析及站点配置 |
| `scripts/` | 校验、构建、生成目录与预览 |
| `dist/` | 本地静态构建结果，不提交 |

## 公开范围与许可

ZIP 原样保存在公开源码仓库，部署不携带 ZIP，也不提供 ZIP 下载入口。阅读页面不显示制作要求或画面提示词，但这些内容若存在于原 ZIP，仍可被下载查看；提交前请先检查整个 ZIP。

代码采用 [MIT 许可](LICENSE)。作品文字、图片和其他资料不自动适用代码许可；署名、来源及使用条件见作品和 PR 的说明。收录标准及更正方式见 [内容说明](CONTENT_POLICY.md)。

新版拾趣单一 ZIP 的公开署名、来源许可、转载条件、联系/作品链接、AI 披露、原文与版本会在阅读页保留。投稿者与制作人分开，缺少制作署名时显示未署名。原始 WebP/XMP 保持不变，声明的最终图片哈希不符时拒绝解析。元数据和哈希不构成权属认证。

所有线上作品在构建时校验声明的图片 SHA-256，公开清单为每幅图片记录最终字节摘要和固有宽高。线上阅读使用稳定 HTTP 地址和浏览器缓存，不为核验哈希提前下载全部图片。本地 ZIP 试读继续使用受限解压和 Blob URL，完全留在当前浏览器。
